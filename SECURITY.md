# Security Policy

## Reporting a vulnerability

Please do **not** report exploitable security vulnerabilities in a public issue, discussion, or pull request.

Use the private security reporting feature on the official GitHub repository if it is enabled. If it is unavailable, contact the maintainers through a private contact method published on the official project website:

https://vertexdev-studio-website.vercel.app/

Include as much of the following as you can safely provide:

- Affected version or commit.
- Impact and conditions required to reproduce the issue.
- Minimal reproduction steps or a proof of concept.
- Relevant logs with tokens, passwords, IP-sensitive details, and personal data removed.
- Any suggested mitigation.

Please do not publicly disclose the vulnerability before the maintainers have had a reasonable opportunity to investigate and prepare a fix.

## Scope

Examples of issues worth reporting privately include authentication bypass, privilege escalation, exposure of secrets, unsafe API access, remote code execution, and vulnerabilities that affect proxy or server availability.

Do not use a vulnerability report to test systems you do not own or have permission to assess.

## Response expectations

The project is maintained on a best-effort basis. No guaranteed response or remediation deadline is promised. Please keep the report confidential while a fix is being investigated.
